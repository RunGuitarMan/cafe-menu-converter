# Ревью и завершение реализации — 13.10.2026

## Состояние на старте

В репозитории были Core-модели, PdfTextReader, парсеры названия/состава/выхода/КБЖУ/цены и 58 тестов. Они проходили. Парсер документов целиком, валидация меню, экспорт, приложение и публикация отсутствовали; исходный проект нельзя было использовать для конвертации.

План предыдущего агента также содержал неподтверждённое предположение о различимых именах шрифтов. В реальных PDF PdfPig возвращает `Type3` для названия, цены и состава. В реализации используются подтверждённые размеры (11, 10.5 и 9 pt), белый цвет разделов и координаты. Чтение слов дополнительно разделяет смену шрифта и поддерживает отмену между страницами.

## Уточнения требований

В ходе текущего ревью пользователь подтвердил: категории берутся дословно из PDF; специальные исключения для ошибочной яичницы не нужны. Поэтому нет классификации по словам «каша», «блины» и нет удаления `Т БАНК` из конкретного названия. Конфиг задаёт допустимые заголовки, а не преобразование категорий.

## Реализовано

- Геометрический разбор обоих макетов, группировка по дате, переносы названия/состава/КБЖУ между колонками и страницами.
- Проверки полноты, неизвестных строк/разделов/выхода, наличия цены и КБЖУ; ошибки блокируют экспорт.
- XLSX по образцу с 14 текстовыми колонками и безопасной заменой файла после полной записи.
- GUI с выбором офиса, файловыми диалогами, drag-and-drop, фоновым выполнением, отменой, сводкой, списком блюд и диагностикой.
- Автономные сборки win-x64 и osx-arm64, конфиг, инструкции и ad-hoc подпись macOS.
- Avalonia обновлена до 11.3.22. Она использует исправленный Tmds.DBus.Protocol 0.21.3; предупреждение NuGet об уязвимости старой зависимости не подавлялось. DataGrid остаётся совместимой версии 11.3.13.
- В автономных сборках закреплён доступный runtime .NET 10.0.12 вместо 10.0.0 из установленного SDK.

## Доказательства и ограничения

PdfPig и независимый pdfplumber-парсер совпали по всем полям всех 300 блюд. Независимый проверочный скрипт сохранён в `tools/verification/audit_pdf.py`; он служит только для аудита фиксированных референсов, приложение не зависит от Python. Golden-тесты сравнивают все 14 выходных полей и исходную страницу. Рендеры страниц использовались для проверки макета, переносов и аномалий. Это не утверждение о ручной вычитке каждого символа.

Проверены: завтрак 145 блюд, 2 ожидаемых предупреждения; обед 155 блюд, без предупреждений. OpenXmlValidator принимает сохранённый XLSX, обратное чтение совпадает по каждой ячейке. Заголовок сверяется с предоставленным XLSX. Проверки повреждённых данных и отмены подтверждают отсутствие частичного результата.

Готовая автономная `.app` запущена на macOS Apple Silicon. Через GUI сохранены оба меню, проверены системный диалог выбора PDF, список блюд, предупреждения и отмена перезаписи. Сборка Windows подтверждена как PE32+ GUI x86-64; macOS — Mach-O arm64. Проверка `codesign --verify --deep --strict` проходит. Проверка NuGet с транзитивными зависимостями не обнаружила известных уязвимых пакетов на дату ревью.

Границы: конкретный текстовый шаблон PDF, без OCR и автоматического исправления исходных данных. Произвольные новые шрифты/вёрстку нельзя считать поддержанными без новых референсов. Windows требует отдельной проверки запуска на реальной Windows-машине.
